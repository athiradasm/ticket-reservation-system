# Development Plan

## Scope
Build a ticket reservation application in small, testable increments. Confirm the exact ticket domain (bus, train, or event tickets) and technology stack against the laboratory brief.

## Milestones

### Milestone 1 — Planning
- [ ] Confirm ticket domain and project requirements
- [ ] Identify user roles and permissions
- [x] Draft storyboard
- [ ] Choose technology stack and database

### Milestone 2 — Interface
- [ ] Create landing page
- [ ] Create registration and sign-in screens
- [ ] Create search and results screens
- [ ] Create booking review and confirmation screens

### Milestone 3 — Core functionality
- [ ] Implement authentication securely
- [ ] Implement search and availability
- [ ] Implement ticket/seat selection
- [ ] Implement booking creation and unique references
- [ ] Implement booking history and cancellation

### Milestone 4 — Payment and quality
- [ ] Use a sandbox or simulated payment flow only
- [ ] Validate inputs and handle errors
- [ ] Test authorization and prevent users accessing other users' bookings
- [ ] Test booking and cancellation edge cases
- [ ] Prepare final demonstration

## Definition of done
A feature is done only when implemented, tested with relevant cases, and documented. Update `docs/progress.md` after each laboratory session.
